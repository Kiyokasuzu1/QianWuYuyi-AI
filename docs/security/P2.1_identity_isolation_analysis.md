## 1. 当前身份流程图

```
QQ 消息（用户 A）
 ↓
AstrBot（astrbot_plugin_yuyi/main.py:14）
    user_id = event.get_sender_id()      # 平台差异时可能为 None/空
    payload = {"user": str(user_id)}     # str(None) → "None" 直通风险
 ↓ HTTP POST /v1/chat/completions (api_server.py:810)
 ↓
身份规范化（api_server.py:818-826，R2.7.6-AUDIT）
    raw_user = data.get('user', None)
    None / "" / 非(str,int)  →  "default"     ← 占位符统一入 default 桶
    其余                      →  str(raw_user) 直通   ← 无格式校验、无沙盒
 ↓
三条处理链（依次降级）：
    [phase4_enabled=true] RuntimeController.handle_message(uid)
        → data/users/<uid>/{memory,personality,relationship}_<uid>.json（目录级隔离）
    [降级] RuntimePipeline.run(user_id=...)
    [降级] orchestrator.process(msg, user_id=...)
        → MemoryStore 单文件 data/memory.json（记录级 user_id 字段过滤）
 ↓
后续状态更新链（不分用户或部分分用户）：
    emotion 更新 → emotion_state.json（全局）
    growth 评估 → experience_journal.jsonl / proposals/（全局队列，记录带 user_id 字段）
    self_model → self_model.json（全局）
    relationship → users/<uid>/relationship_*.json（Phase4 分用户）+ relationship_state.json（全局）
```

旁路入口：
- `/initiative`（api_server.py:1006）：`user_id = data.get('user_id', 'default')` — 同样直通+default 兜底
- Agent Server（端口 8765，Phase 7.2.1-p2 由 api_server 拉起）
- `/admin/api/*`（screen/control 六端点）：已有 **fail-closed 鉴权**（`_require_admin_auth`：YUYI_ADMIN_TOKEN / config admin.token / 未配置时仅回环）——不涉用户身份，非本阶段问题
- `/v1/models`、`/health`、`/dashboard_v2`：无身份语义

身份失败处理分类（按勘察口径）：
- 占位符（None/""/非法类型）→ **C：进入默认用户 default**
- 任意字符串（"1234"、"qq_366648462"、乱码）→ **直通建桶**（无界 C 变体：每个字符串一个数据目录）
- 无 A（拒绝请求，除 messages 缺失的 400）、无 B（隔离沙盒）、无 D（丢弃）

## 3. 推荐架构：Identity Resolver

新增 `src/security/identity.py`（纯函数模块，零业务依赖，与 src/version.py 同风格）：

```python
@dataclass(frozen=True)
class Identity:
    id: str          # 解析后的用户标识（沙盒时为 "_unknown_sender"）
    source: str      # user_passed | placeholder | unknown
    verified: bool   # 是否通过格式校验（QQ 5~12 位纯数字）
    permission: str  # creator | known_user | stranger | sandbox

def resolve(raw_user, *, config=None) -> Identity
```

解析规则：
1. 环境缺失/占位符（None/""/default/none/null/未知…）→ `_unknown_sender`，permission=sandbox
2. 纯数字且 5~12 位 → 真实 QQ：白名单（366648462=creator）→ known/stranger 原样使用
3. 非法格式（4 位、13 位、非纯数字）→ `_unknown_sender` 沙盒
4. `single_user` 显式模式（config 开关，默认关）：仅占位符兜底为 creator，真实 QQ 仍原样（p6sec T3 契约）

沙盒存储：`data/sandbox/_unknown_sender/`（与 data/users/ 完全分离；沙盒数据不进入 growth/self_model/emotion 链）。

版本依据：p6sec 契约（tests/test_p6sec_user_id_safety.py + tests/test_api_server_user_id_fallback.py，当前在 v1.0 树内、21F，即 A-3 的验收测试）。
