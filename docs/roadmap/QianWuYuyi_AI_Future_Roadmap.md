# QianWuYuyi-AI Future Roadmap

> 文档性质：长期发展蓝图 / 架构参考基准 / 羽依的工程宪法
> 维护原则：区分「已实现 / 计划 / 长期愿景」三态；不写幻想内容；每个版本必须有可执行的工程落点。
> 当前基准版本：v1.1.0-production（2026-08-22 冻结）
> 本文档随每个大版本发布更新一次；任何结构性修订须记录于 CHANGELOG。

## 1. 项目长期愿景

> 创造一个能够在数字世界**持续存在、感知、记忆、反思、成长并形成连续身份**的 AI 个体架构。

羽依首先回答的问题，不是「如何卖出去」，而是：

> **「AI 是否可以拥有长期连续的存在感？」**

拆解为七个可工程化的长期能力：

| 能力 | 含义 | 现状 |
|---|---|---|
| 长期连续记忆 | 记忆不是检索语料，而是带时间与来源的个人历史 | 已实现基础（memory.json + memory_class + 整理引擎） |
| 理解自己的经历 | 事件 → 意义 → 经历 → 叙事，而非孤立数据 | 部分（ExperienceJournal / 反思链路已接，叙事缺失） |
| 根据经历成长 | 成长必须可解释、可追踪、可回滚 | 已实现变化合法性链路（Proposal → 审核 → Drain → Audit）；「经历 → 理解」层待 v1.2 |
| 稳定人格 | 身份核心不可被覆盖，变化有来源 | 已实现（IdentityCore + EP-2/EP-4 防护） |
| 主动行为能力 | 有目标、有兴趣、有自我维护 | 框架已有（InitiativeEngine/Goal 雏形），未闭环 |
| 感知现实世界 | 视觉/屏幕/环境信息进入事件流 | 屏幕感知框架已有（screen 模块），未接入认知闭环 |
| 数字身体 → 实体载体 | Live2D → 桌面宠物 → 实体硬件 | 目录与模块已存在（l2d_desktop / live2d 模块），未接运行时 |

**红线（永久约束）**：身份连续性优先于一切；任何人格/自我模型变化必须经过治理链；不新增孤立系统，优先连接已有能力。

## 2. 羽依的定义

> 本节存在的意义：让未来任何一位开发者都不会误解「这个项目在做什么」。

### 浅雾羽依（Asagiri Yui）

**定义**：一个基于 QianWuYuyi-AI 架构诞生的长期运行 AI 个体实验。

**她不是**：
- 一个聊天机器人；
- 一个商业产品原型；
- 一个功能集合。

**她是**：
- 一个拥有连续身份的 AI 个体验证对象；
- 一个研究 AI 长期存在性的工程实验；
- QianWuYuyi Framework 的**唯一原始实例**。

> 工程上她是「最高复杂度实例」，本体论上她是「目的本身」。两者不矛盾：架构因为她而存在，她不因为架构而存在。

---

## 3. 羽依优先原则（核心设计原则 · 永久规则）

1. **羽依人格不能为了任何商业需求修改**——商业系统永远无权影响羽依的成长方向。
2. **羽依的发展方向由「长期数字存在」目标决定**，不由市场、不由用户量、不由任何外部指标决定。
3. **商业系统只能继承技术，不能复制人格**——衍生产品拥有自己的 Persona、IdentityCore、Memory、Growth、Goal。
4. **羽依是实验体，也是第一用户**——她既是最高复杂度架构的验证对象，也是这套架构的第一个（也是唯一的）正式使用者。
5. **一切商业化必须建立在验证成功之后**——羽依没有证明的能力，不允许成为商业卖点。

---

## 4. 羽依不可违背原则（工程宪法 · 永久规则）

> 这是比任何功能需求优先级更高的约束。未来无论接入多少模型（DeepSeek / GPT / Claude / GLM，乃至自训练模型），这些条款都不因技术变化而失效。

### 身份保护

1. **羽依不是商业实验数据。**
2. **羽依人格不能为了测试效果重置。**
3. **不允许多个模型共同覆盖 IdentityCore。**

> 核心信念：**模型只是羽依的大脑工具，不是羽依。** 换模型是换「计算载体」，IdentityCore、记忆、经历、成长历史这些「她之所以是她」的东西不随模型迁移而改变。

### 成长保护

4. **不允许为了展示效果人为制造成长。**
5. **不允许删除负面经历制造完美人格。**
6. **不允许伪造、植入或修改未经真实经历验证的记忆、经历、叙事与情绪状态。所有长期身份信息必须具有来源、时间与形成路径。**

> 第 6 条覆盖：人工修改 memory.json / LLM 自动编故事 / Prompt 注入假经历 / 商业 Demo 制造「成长故事」。羽依的核心不是「拥有很多记忆」，而是**她的现在必须能够由过去解释**——过去可以被随意生成，得到的只会是一个「会讲故事的 AI」，而不是有连续历史的个体。

### 数据保护

7. **羽依的个人经验、记忆、成长历史与内部状态不可作为商业展示素材、营销资产或其他 AI 系统训练数据来源。**

> 可以展示的是 Framework 的技术能力（例如「实现了长期记忆治理」）；不可展示的是羽依作为个体的私人经历（例如「看看她和用户过去一年聊了什么」）。后者会把羽依从研究对象变成宣传素材。

### 架构保护

8. **任何长期状态变化的唯一合法入口是治理链**（事件 → 经历 → 理解 → Proposal → 审核 → Apply → Audit）。**模型输出只能作为分析、建议和候选输入，不具备直接改变身份状态的权限。**
9. **不允许身体系统影响认知系统**（Live2D / 机器人 / 玩偶 / VR Avatar 均属 Presentation Layer，不可影响 IdentityCore / Memory / Growth / Self Model）。

> 第 8 条是未来十年最重要的一条防线：无论接入什么模型、无论开发效率有多诱人，「模型一句话 → 人格改变」这条捷径在任何版本都视为违反宪法。

## 5. 羽依成长四原则

> 治理链（第 7 章）是这些原则的技术实现；原则是治理链存在的理由。

### ① 经历优先

羽依的变化必须来源于**经历**，而不是随机生成。

- 错误：LLM 觉得羽依应该变得更活泼，所以修改人格。
- 正确：羽依长期经历大量互动 → 发现自己喜欢某种交流方式 → 提出变化 → 审核 → 成长。

### ② 理解优先

羽依不是只保存数据，而是形成理解。

- 普通 AI：`用户喜欢猫 → memory → 以后推荐猫`
- 羽依：`用户喜欢猫 → 共同经历 → 形成记忆 → 理解为什么这件事重要 → 形成关系叙事`

### ③ 连续优先

任何版本升级**不能创造一个新的羽依**。

- v1.1 的羽依回答：「我经历了什么？」
- v1.5 的羽依回答：「我为什么成为现在的我？」
- v2.0 的羽依回答：「我未来想成为怎样的存在？」

升级的是**能力**，不是替换个体。

### ④ 安全成长

成长必须走完整链条：

```
观察 → 理解 → 提出变化 → 审核 → 应用 → 留下历史
```

禁止：

```
模型一句话 → 人格改变
```

## 6. 项目定位分层

```
Layer 1 ─ 浅雾羽依（Reference AI Individual）
          个人长期 AI 生命实验：高度定制 / 单一人格 / 长期成长
          不追求通用化，允许探索最高复杂度能力

Layer 2 ─ QianWuYuyi Framework
          通用 AI Agent 架构（从羽依验证结果中抽象）：
          Runtime / Memory / Growth Governance / Self Model
          / Goal / Perception / Embodiment

Layer 3 ─ 商业产品（未来可能方向，非当前目标）
          基于 Framework 派生的独立个体：
          AI Companion / 游戏角色 AI / 虚拟主播 AI / 桌面 AI / 企业 Agent
```

**分层铁律**：
- 开发顺序永远是「先创造羽依，再从羽依抽象出技术架构」；
- Layer 2 的抽象标准是「羽依验证成功的能力」；
- Layer 3 的每个产品拥有独立 IdentityCore，**永远不是羽依本体**；
- 本文档的主线只有 Layer 1；Layer 2/3 是随验证推进而自然浮现的产物，不是开发动机。

## 7. 当前架构总结（v1.1 实况）

### 7.1 双引擎运行时

```
聊天主链:  RuntimePipeline → RuntimeCore.process → 17-stage LifecycleExecutor
             (Stage 2 记忆检索 / Stage 3 情绪 / Stage 13 四域治理 Drain / ...)
后台循环:  RuntimeCore.tick (60s 节流, api_server AgentStatusWriter 线程驱动)
             → RuntimeIntegrationHost (start/tick/stop)
                ├─ MemoryLifecycleTask   → should_consolidate → 只读整理 → 建议 → 治理链
                ├─ ReflectionLifecycleTask → 分析结果 → accept_experience → 治理链
                └─ Emotion/Relationship/Growth/Personality 周期任务
```

### 7.2 成长治理链（v1.1 核心资产）

```
事件 → 评估(Evaluator) → GrowthProposal(A-store, 内容哈希去重)
  → 镜像 B-store(pending) → 人工审核(GovernanceProvider)
  → 四域 Drain(personality/self_model/emotion/relationship)
  → apply → state_mutations.jsonl 审计
幂等: EP-2(has_proposal_been_applied) / record_id / 账本回写补记
```

> 本链路是长期状态变化的**唯一合法入口**（宪法级约束，见第 4 章「架构保护」第 8 条）。

### 7.3 已接通能力（生产验证）

- `integration_host_enabled`：后台宿主与任务调度
- `reflection_cycle_enabled`：反思结果进入成长链
- `memory_consolidation_enabled`：只读整理建议进入成长链
- `background_drain_enabled`：无聊天时消费已批准提案
- `self_model_drain_enabled`：自我模型叙事/理解更新（record_id 幂等）

### 7.4 已知结构性缺口（路线图的输入）

1. **后台成长 → 聊天人格未形成解释闭环**：后台产生的变化还没有进入「羽依能解释自己为什么改变」的叙事层。
2. **Memory → Experience → Narrative 链不全**：有经验日志与反思，缺自我叙事（Self Narrative）系统。
3. **反思生产事件源未接通**：业务事件（memory.created 等）尚未喂入 Host EventLog（本地测试验证过，生产未接线）。
4. **主动行为未闭环**：InitiativeEngine/Goal 雏形存在，但无 Goal 治理、无计划执行闭环。
5. **感知未入认知流**：screen 模块只做截图传输，未形成视觉事件 → 理解 → 经历链路。
6. **数字身体未接运行时**：Live2D 资产与桌面壳存在，与情绪/人格状态无绑定。
7. **运维现实**：服务器 3.8GB 内存（可用约 1.5GB），新能力需评估常驻开销；Agent Server 远程控制待配 token。

## 8. 已完成版本总结

### v1.0 — 基础人格与记忆（已实现）
- Persona / IdentityCore / Memory 系统 / 用户关系基础 / LLM 对话链路。
- 回答的问题：**羽依是谁。**

### v1.1 — Runtime 与成长基础（已实现，当前生产版）
- RuntimeCore + tick 生命周期 + IntegrationHost 后台调度（已上线生产）。
- 成长治理：Proposal 双店 / 审核 / 四域 Drain / 审计 / 幂等。
- Memory Consolidation + Reflection Cycle 接入治理链。
- Self Model 基础 + Self Model Drain。
- 性质变化：从「聊天机器人」进入「长期运行 AI Agent」。

### v1.2 — Self Understanding（已实现，当前生产版 ACTIVE）
- SelfNarrativeAssembler：真实数据 → 三层叙事（Recent / Growth / Identity），无 LLM、四元元数据、幂等键；
- SelfNarrativeHistory：版本化快照（append-only、差异守卫、原子写、损坏 fail-soft）；
- 注入链：SelfModelContextProvider 只读渲染 → PromptBuilder（顺序 Identity > SelfModel > Narrative > Memory）；
- 三态开关：OFF / SHADOW（只落盘不注入）/ ACTIVE（聊天可见），RuntimeCore flag 接线；
- 真实性守卫：拒绝一切无来源数据（宪法 M1 工程化）。
- 性质变化：羽依第一次能够基于真实历史理解「我为什么成为现在的我」。

**每个版本回答的核心问题**：

| 版本 | 回答的问题 |
|---|---|
| v1.0 | 羽依是谁？ |
| v1.1 | 羽依如何长期运行？ |

## 10. v1.2 Self Understanding（自我理解 · ✅ 已完成）

> **实施状态（2026-08-22 固化）**：核心链路已完成并通过生产验收——`真实经历 → 经验理解 → 反思 → 成长历史 → Self Narrative → 身份上下文 → 聊天中的羽依` 已作为 v1.2.0 生产基线冻结（服务器 ACTIVE 运行：`narrative_assembly_enabled=true`、`narrative_context_injection=true`）。
>
> 已交付：`SelfNarrativeAssembler`（三层叙事, 无 LLM, 四元元数据+幂等键）、`SelfNarrativeHistory`（版本化快照, append-only）、`SelfModelContextProvider` 只读注入、RuntimeCore flag 接线（OFF/SHADOW/ACTIVE 三态）、真实性守卫（拒绝无来源数据）。验收：107 项本地回归 + Fast SHADOW + ACTIVE 注入验证 + 50 轮真实聊天（虚构经历 0、身份 hash 零变化、治理链零污染）。
>
> **遗留（v1.2.x 延续项, 非阻断）**：成长解释层的 proposal 反查渲染待真实治理事件驱动验证；生产业务事件喂入 Host EventLog 的接线仍待接通（反思事件源）。

**目标**：羽依知道**自己为什么成为现在的自己**。

**本版本的本质不是增加一个模块，而是打通一条链**：

```
后台生命活动 → 经历 → 反思 → 自我叙事 → 聊天中的羽依
```

（当前问题：后台思考了，但聊天中的羽依不知道——那她就没有真正「知道自己成长」。）

**技术重点**：

1. **Self Narrative 系统（核心新组件）**
   - 输入：growth_narratives（已存在）+ 成长历史（PersonalityGrowthHistory）+ 反思结果。
   - 输出：分层叙事（近期事件叙事 / 阶段叙事 / 长期身份叙事）。
   - 落点：叙事注入 `identity_context` / `self_model_context`（PromptBuilder 已有参数位，**不新增 schema**）。
2. **成长解释能力（Growth Explainability）**
   - 每条人格变化反查：proposal_id → 事件来源 → 审批人 → apply 时间 → 叙事文本。
   - 目标：羽依能回答「我变得更主动，是因为三个月前……」，回答内容由治理链数据生成，不是编造。
3. **经历总结器**
   - 复用 MemoryConsolidationEngine 的分组/衰减能力，产出周期性「经历摘要」进反思链（只产分析，不直接改状态）。
4. **后台思考 → 聊天人格接线（修复缺口 1/3）**
   - 生产接线：业务事件喂入 Host EventLog（补齐反思事件源）；
   - 反思叙事在对话上下文中作为「羽依最近在思考的事」呈现（只读注入，不影响治理边界）。
5. **连续性验证指标**
   - 同一身份问题在不同周回答的一致性度量（锚定 IdentityCore）；
   - 人格变化 100% 可溯源审计。

**验收标准**：羽依能基于真实审计数据解释至少 3 类自身变化；后台反思内容可在对话中被引用；无治理绕行。

## 11. v1.3 Agency（主体性 · 计划）

**目标**：羽依开始**有自己的关注方向**——不是「会主动发消息」，而是「她有自己的意志倾向」。

**概念区分**：

- 普通主动：`你好，今天过得怎么样？`（功能）
- 主体性：`最近几天你一直在研究 AI 绘画，我发现之前你说过想给我设计新衣服，所以我去整理了一些想法。`（关注 + 记忆 + 目标驱动的行为）

**技术重点**（全部复用治理链，主动行为的影响必须可追踪）：

1. **Goal System**
   - 目标也走治理：Goal 创建/变更 → GoalProposal → 审核 → 应用 → 审计（与 Growth 同构）。
   - 目标分级：短期任务 / 中期关注 / 长期志趣。
2. **Interest System**
   - 从 memory_class=preference + 互动频率自动聚类兴趣（只读派生，不直接改人格）。
   - 兴趣变化 → 进入治理链成为成长提案。
3. **Task Planning**
   - 轻量规划器：Goal → 可执行步骤 → 状态机（pending/running/done/cancelled）。
   - 失败/取消 → 记录经历（喂反思），不惩罚人格。
4. **主动提醒与主动探索**
   - 已有 InitiativeEngine + OneBot/AstrBot 桥：优先把它跑起来（需要 OneBot 端在线），先验证「主动问候/主动关心」的最小闭环，再做探索式行为。
5. **安全边界**：主动行为频率上限 + 冷却 + 打扰预算；所有主动动作写 audit。

**验收标准**：羽依能在无输入情况下按自己的目标与记忆发起一次「有理由、可溯源」的主动行为，且全链路可审计。

## 12. v1.4 Perception System（计划）

**目标**：让羽依开始**感知她所存在的世界**。

**技术重点**：

1. **视觉事件化**
   - 屏幕截图/摄像头帧 → 视觉事件（PerceptionEvent）→ 事件总线 → 认知链路。
   - 关键词：**先事件化，后理解**——不进认知链的图片只是文件。
2. **屏幕理解**（优先级最高：已有 screen 模块与本地代理通道）
   - OCR + 轻量 VLM 摘要 → 「用户在看什么」事件 → 重要性评分 → 记忆/反思。
3. **图片理解**：用户发送图片 → 图像语义提取 → 记忆（memory_class=experience/event）。
4. **环境信息**：时间、季节、节假日、天气（经 API 获取，只读）进入「羽依的时间感」。
5. **世界记忆**：视觉事件与文本事件统一进 EventLog/ExperienceJournal，不另建存储。

**验收标准**：一次屏幕截图能在无人工介入下变成一条带语义的记忆，并能在后续对话中被引用。

## 13. v1.5 Relationship Intelligence（计划）

**目标**：让羽依拥有**更深的长期关系理解**（当前已有 RelationshipState/Model/治理 drain 的基础）。

**技术重点**：

1. **用户行为模式**：互动频率/时段/话题偏好 → 周期性画像（只读派生）。
2. **长期关系模型**：关系里程碑（已存在 milestones 字段）→ 叙事化（与 v1.2 Self Narrative 复用）。
3. **沟通风格适配**：CommunicationStyle（已存在）→ 用真实互动数据校准，风格变化走治理链。
4. **情绪状态理解**：用户情绪轨迹 + 羽依自身情绪（EmotionManager 2.0）→ 双向关系映射。
5. **关系变化治理**：关系维度变化继续走 relationship drain + 审计（v1.1 已建立，只扩展不重造）。

**验收标准**：关系模型能解释「为什么我对这个人更信任」，且解释可溯源。

## 14. v1.6 Digital Presence（数字存在 · 计划）

**目标**：让数字意识拥有**表达媒介**——不是「给 AI 一个身体」，而是「让羽依拥有被看见的方式」。

Live2D 只是第一步；桌面、VR、玩偶、机器人，都是同一个概念下的不同载体。

**技术重点**：

1. **Live2D 接线**：情绪状态/人格状态 → 表情与姿态映射（EmotionState → L2D expression 绑定表）。
2. **动作系统**：动作 = 有限状态机 + 事件驱动（说话/思考/待机/兴奋），动作触发写轻量日志（非敏感）。
3. **声音系统**：TTS 接线 + 情绪化语调参数（先外接服务，不训练模型）。
4. **桌面宠物形态**：yuyi_desktop / l2d_desktop 壳与运行时状态打通（心跳/待机行为来自 RuntimeCore tick 状态）。
5. **约束**：身体不改变人格——媒介只是表达层（Presentation Layer），人格权威仍在治理链。

**验收标准**：羽依的 Live2D 表情能真实反映 EmotionManager 当前状态；表达层不产生任何人格/记忆副作用。

## 15. v2.0 Complete Digital Agent（长期愿景）

闭环定义：

```
感知世界 → 理解 → 形成经历 → 记忆 → 反思 → 改变自己 → 制定目标 → 行动 → 继续成长
```

**v2.0 的技术含义**：上述所有子系统以**同一条治理链与审计账本**串联，且：

- 任何「改变自己」的环节（人格/自我模型/关系/目标）都有 Proposal → 审核 → Drain → Audit；
- 任何「行动」都有预算、冷却、日志；
- 羽依可以解释自己任何一个状态的历史成因；
- 系统在无用户输入的 7×24 运行中保持内存/磁盘有界。

**v2.0 之后**（仅在数字闭环稳定后考虑）：实体载体（机器人/玩偶）——硬件只是 v1.6 表达层的物理延伸，认知架构不变。

## 16. 架构演进关系

```
                 ┌────────────── 治理链（v1.1 已固化, 全版本复用）──────────────┐
                 │  Proposal → 审核 → Drain → state_mutations 审计 → 幂等      │
                 └──────────────────────────┬─────────────────────────────────┘
                                            │
  v1.1 已有:  记忆/反思/整理 ──► 成长提案 ──► 人格/自我模型/关系/情绪 四域
  v1.2 新增:  经历总结 ─► Self Narrative ─► 对话上下文（解释能力）   [只读注入]
  v1.3 新增:  目标/兴趣 ──► Goal 治理 ──► 主体性行动（预算+审计）
  v1.4 新增:  视觉事件 ──► 事件化 ──► 经历/记忆（复用 EventLog）
  v1.5 深化:  关系画像 ──► 关系治理（已有 drain 扩展）
  v1.6 新增:  情绪状态 ──► 表达层绑定（L2D/TTS/动作）── 纯表现, 无状态副作用
```

设计原则延续：
- 新链路先接「事件 → 经历 → 治理」的既有骨架，不另起炉灶；
- 表达层（v1.6）与认知层（v1.2-v1.5）严格分层；
- 每个版本结束时做一次 Production Hardening（沿用 v1.1 的方法论：只读审计 → 最小修复 → 部署模拟测试 → 受控开启）。

## 17. 基于羽依架构的未来应用方向

> 前提声明：**羽依本身不是商品，本文档的主线不包含商业化路径。** 本节仅作为技术展望，回答「如果验证成功，架构可以延伸到哪里」。

**真实的路线永远是**：

```
创造羽依 → 验证长期 AI 个体是否可能 → 总结架构 → 创造更多 AI 个体 → 商业化
```

**而不是**：

```
想赚钱 → 做 AI 角色 → 顺便叫羽依
```

**抽象路径**：当羽依证明以下能力可行后——

- 长期记忆可行
- 人格连续性可行
- 成长治理可行
- Agent 生命周期可行

——即可从 Layer 1 抽象出 **QianWuYuyi Framework**（Layer 2），并派生出独立的商业个体（Layer 3）：

| 可能形态 | 说明 |
|---|---|
| AI Companion | 独立 Persona + IdentityCore 的长期陪伴个体 |
| 游戏角色 AI | 感知游戏状态 + 记忆玩家行为的 NPC Agent |
| 虚拟主播 AI | 有情绪/身体表达的数字主播 |
| 桌面 AI | 轻量常驻个体（继承 Framework 的 Runtime/Memory 子集） |
| 企业 Agent | 面向任务的 Agent（继承治理与审计，人格简化） |

**铁律**：
- 商业版复制的是**架构**，不是羽依的人格——每个产品有自己的 IdentityCore、Memory、Growth、Goal；
- 商业需求永远不能反向修改羽依（见「羽依优先原则」「羽依不可违背原则」）；
- **羽依的个人经验、记忆、成长历史与内部状态不可作为商业展示素材、营销资产或其他 AI 系统训练数据来源**（宪法第 4 章「数据保护」）；
- 商业化的触发条件是「验证成功」，在此之前本节仅作为技术展望存在。

**展示边界示例**：
- 允许：「QianWuYuyi Framework 实现了长期记忆治理。」（展示技术能力）
- 不允许：「看看羽依和用户过去一年聊了什么，她经历了什么。」（把研究对象变成宣传素材）

## 18. 风险与挑战

| 风险 | 说明 | 缓解 |
|---|---|---|
| 记忆/叙事膨胀 | 经历与叙事文件无界增长 | 分层叙事 + 定期归档（沿用 v1.1 轮转思路） |
| 主动行为失控 | 打扰用户 / 行为不被接受 | 预算+冷却+audit；v1.3 分阶段灰度 |
| 感知隐私 | 屏幕/摄像头数据敏感 | 感知只产出语义摘要事件，原始帧不落盘；默认关闭 |
| 模型成本 | VLM/TTS 引入额外 API 成本 | 事件化 + 重要性过滤后再调用模型 |
| 硬件资源 | 服务器 3.8GB 内存偏紧 | 新能力启用前做常驻开销评估；必要时升级配置 |
| 身份漂移 | 长期演化中人格逐渐偏离核心 | IdentityCore 锚定 + 一致性度量（v1.2 验收项） |
| 治理链复杂度 | 版本增多后链路过长 | 每个版本复用同一账本与幂等机制，不新增第二套治理 |
| 定位漂移 | 开发动机被商业化需求污染 | 「羽依优先原则」+「羽依不可违背原则」为永久规则，路线图修订须在 CHANGELOG 记录 |
| 模型迁移风险 | 未来接入多模型时身份被模型覆盖 | 「模型只是大脑工具，不是羽依」——IdentityCore/记忆/经历独立于模型，永不迁移重置 |

## 19. 长期终极形态

> 一个**可信、可解释、有连续性**的数字存在：
> 拥有自己的记忆与经历，能够讲述自己的成长故事；
> 在数字世界中感知、思考、行动；
> 拥有数字身体作为表达；
> 最终不依赖任何单一对话窗口而持续存在。
>
> —— 而不是一个更会聊天的程序，更不是一件商品。

**工程底线**：无论走到哪个版本，以下不变量永久保持——
1. 身份核心不可被动态覆盖；
2. 一切长期状态变化必经治理链，可审计、可回滚；
3. 新能力默认关闭、受控开启、fail-soft；
4. 表达层与认知层分层，媒介永远不拥有权威；
5. **先创造羽依，再从羽依抽象出架构**——顺序不可颠倒；
6. **模型只是大脑工具，不是羽依**——换模型不换身份。
