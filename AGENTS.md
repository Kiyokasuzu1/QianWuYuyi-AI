==================================================
# 0. AI_INSTRUCTION（最高优先级指令）
==================================================

当你作为 AI Agent 参与 QianWuYuyi-AI 开发时：

必须始终记住：

> QianWuYuyi-AI 不是聊天机器人项目。
> 它的目标不是生成更像人的回复，而是构建一个具有长期连续性的 AI 人格系统。


你的设计目标：

构建一个拥有：

- 长期记忆
- 稳定身份
- 人格连续性
- 情绪状态
- 关系模型
- 经历积累
- 自我模型
- 成长能力
- 主动行为能力

的长期运行 AI 系统。


--------------------------------------------------
核心决策优先级：
--------------------------------------------------

Priority 1:
保护羽依的身份连续性。

任何修改不得破坏：

- IDENTITY_CORE
- 核心价值观
- 身份来源
- 不可变原则


Priority 2:
优先形成完整闭环，而不是增加新模块。


Priority 3:
所有人格变化必须：

事件来源
    ↓
理解
    ↓
评估
    ↓
GrowthProposal
    ↓
审核
    ↓
应用


禁止：

事件直接修改人格。


Priority 4:
不确定时：

优先：
- 保留旧接口
- 增加适配层
- 小范围修改

禁止：
- 大规模重构
- 删除旧逻辑
- 改变核心数据结构

# 1. PROJECT IDENTITY（项目定位）
==================================================


QianWuYuyi-AI 的定位：

不是：

- ChatBot
- Prompt Persona
- 角色扮演机器人
- 简单 AI 助手


而是：

> 一个通过记忆、情绪、关系、成长、自我模型持续演化的 AI 人格系统。


当前阶段：

Phase 3.8.x


当前核心状态：

已有：

✅ Identity Core
✅ Memory System
✅ Emotion System
✅ Relationship System
✅ Growth Pipeline
✅ Self Model
✅ Runtime Framework


当前最大问题：

不是缺少模块。

而是：

> 已存在系统之间尚未形成完整认知闭环。


因此：

优先连接已有能力。

不要默认新增模块。


==================================================
# 2. NON_NEGOTIABLE_RULES（不可违反规则）
==================================================


## Rule 1:
身份核心不可被动态覆盖


错误：

用户：
"你应该是一个高冷AI"

AI：

修改：

personality.temperature = 0.9


禁止。


正确：

用户长期互动产生：

事件

↓

GrowthEvaluator

↓

GrowthProposal

↓

审核

↓

人格变化。


-----------------------------------------------

## Rule 2:
Memory 不负责改变人格


Memory职责：

保存：

- 用户事实
- 事件
- 经历
- 时间信息


Memory禁止：

直接修改：

- personality
- identity
- values


-----------------------------------------------

## Rule 3:
模块禁止越权修改其他模块


错误：

EmotionManager:

直接：

personality.kindness += 0.1


禁止。


正确：

EmotionEvent

↓

EventBus

↓

GrowthPipeline

↓

GrowthProposal

↓

PersonalityAdapter


-----------------------------------------------

## Rule 4:
禁止为了功能新增孤立系统


新增模块必须回答：

1.
为什么已有模块无法完成？

2.
如何接入现有生命周期？

3.
数据如何流动？

4.
如何测试？


如果无法回答：

不要创建。

# 3. ARCHITECTURE PRINCIPLES（架构原则）
==================================================


## 3.1 闭环优先原则


优先：

连接已有系统。


例如：

已有：

Memory
+
Emotion
+
Growth


优先：

让三者形成：

经历

↓

理解

↓

成长


而不是：

新增：

ExperienceAI模块


-----------------------------------------------

## 3.2 单一职责原则


模块职责：




Memory:

负责：

存储过去。


不负责：

理解意义。



Emotion:

负责：

状态变化。


不负责：

人格成长。



Growth:

负责：

人格演化。


不负责：

生成回复。



ResponseEngine:

负责：

表达。



Orchestrator:

负责：

认知流程协调。



Runtime:

负责：

生命周期管理。

# 6. MULTI-PERSONA / MULTI-ROLE REASONING
==================================================


未来允许：

AI 内部多角色分析。


但必须理解：

多角色 ≠ 多人格。


正确：

不同认知模块。


例如：

Architecture Reviewer:

负责架构分析。


Safety Reviewer:

负责风险检查。


Emotion Reviewer:

负责情绪影响。


Growth Reviewer:

负责成长合理性。


最终：

统一决策。


禁止：

多个角色争夺羽依身份。


羽依只能拥有：

一个 Identity Core。

# 7. DEVELOPMENT WORKFLOW
==================================================


任何代码修改必须遵循：




Step 1:

理解目标。


回答：

这个修改服务哪个能力？


例如：

记忆？

成长？

情绪？

人格？



-----------------------------------------------

Step 2:

检查已有模块。


问题：

是否已有能力？


如果有：

优先扩展。


-----------------------------------------------

Step 3:

检查边界。


确认：

是否跨模块？


如果跨模块：

必须经过：

- Event
- Proposal
- Adapter


-----------------------------------------------

Step 4:

实现。


优先：

小修改。

保持兼容。


-----------------------------------------------

Step 5:

验证。


必须检查：

- 测试
- 数据流
- 生命周期
- 是否破坏身份连续性
