## 4. Phase 2 数据来源分析

### 4.1 Memory

- **谁写入**：`src/memory/memory_store.py` → `data/memory.json`（扁平 list 结构，每条带 user_id）；入口为 `Orchestrator.process()` 的记忆落盘步骤，受 **P2.1.3 Memory Gate** 保护（sandbox 拒绝写入）。
- **何时写入**：每轮聊天生成回复后。
- **是否带 user_id**：是（40/40 = 100%）。
- 另有 `src/memory/identity_memory.py` 计划路径 `data/identity_memory.json`（尚未创建，未启用）。

### 4.3 Relationship

## 5. Phase 3 污染风险评估

### R1 default 桶污染 —— **HIGH（服务器侧）**

- 本地活跃 `memory.json` 已无 default 桶（40 条全带 user_id）；历史 default 桶数据已归档于 memory_backup / memory_archive。
- 但**服务器生产仍在旧提交 20322e5**（A-3 插件活跃、P2.1 身份隔离未部署），default bucket 陌生人记忆**仍在持续产生**。这是当前最活跃的污染源，根治手段是 P2.1 修复的生产部署（需另轮审批）。

### R2 测试数据进入生产 —— **HIGH（本地活跃文件）**

以下活跃文件已混入测试数据，影响审计可信度与召回质量：

1. `conversation_history.json`：test_user_p0 / test_user_multi 两个 user_histories（6 条对白）。
2. `experience_journal.jsonl`：76 条中 64 条 test_user、12 条 yuyi（trigger=test 的假行动记录）。
3. `audit/audit_logs.jsonl`：444 条中约 140+ 条测试用户审计（u_rb_test 68 等 + 13 个 test_*_user）。
4. `response_styles.jsonl`：48 条 user_id=unknown（身份解析上线前遗留）。
5. `data/validation/` 31.5 MB 测试产物驻留在数据目录内；`_e2e_tmp_should_not_exist/` 残留；`audit_4_4a/` 测试快照残留。

### R3 历史单用户数据迁移问题 —— **LOW**

- 用户侧数据（memory 40 条）已全部归属 366648462，扁平结构带 user_id，迁移简单。
- 人格侧状态（personality_growth_history 555 条、growth_state、self_model、relationship_state、emotion_state）**无 user_id 且不应有**——它们属于"羽依自身"，与用户数据是两类资产，迁移时须单独归类，禁止按用户拆分。

### R4 未来 Growth 读取污染风险 —— **MEDIUM**

- 污染源头已被 P2.1.3 截断：sandbox 无法写 memory → bridge 不会把污染 record 传给 Growth。
- 但历史提案流 `proposals.jsonl`（4,389 条，无 user_id、有重复）与 growth_history（169 条，无溯源）若被未来回读/审计/重放，将无法区分真实与测试来源。建议归档并标记，不在新链路中回读。

## 6. Phase 4 推荐方案（仅设计，不实施）

### 6.1 推荐目录结构

分两档推进，**本期推荐 A 档（最小变动，零代码改动）**：

**A 档（本期，推荐）**：保持 `data/` 根布局不动（与所有模块的路径常量兼容），新增三个分区，移动**非活跃产物**：

```
data/
├── (活跃文件原位保留)      # memory.json、growth_state.json、users/、emotions/ ...
├── archive/                # 只读归档（不再被任何代码路径读写）
│   ├── memory_backup/      # ← 现有 data/memory_backup
│   ├── memory_archive/     # ← 现有 data/memory_archive
│   ├── proposals_legacy/   # ← data/proposals/（6.7MB 历史流 + .fixed + 备份）
│   └── audit_4_4a/         # ← 测试快照
└── test_artifacts/         # 测试产物（建议移到 data/ 之外，CI 明确排除）
    ├── validation/         # ← data/validation（31.5MB）
    ├── _e2e_tmp_should_not_exist/
    ├── phase376_test/      # 空目录可删
    └── phase721_observation/
```

**B 档（目标态，另轮审批）**：`data/production/{persona, users, global_streams}` 完全重排——需同步修改 8+ 模块的路径常量（memory_store、growth_state、relationship_repository、orchestrator、experience_journal、proposal_store、vector、runtime_core），风险高，必须独立计划与回归。

### 6.2 旧数据迁移决策

| 对象 | 处理方式 |
|---|---|
| **default** | 本地无活跃 default 桶 → 无需迁移。历史 default 桶数据留在 archive 中**保留不删**（遵守"禁止删除任何 memory"）。服务器侧的 default 桶污染在 P2.1 修复部署后自然停止产生 |
