## P2.0 版本统一

目标：
- 三端版本管理统一（GitHub / 本地 / 服务器生产使用同一版本语义）
- VERSION 系统（单一权威版本源，替代当前 VERSION.txt 多块堆叠 + config.yaml `system_version: 7.2.1-p2` + git tag 三套并行）
- 发布流程规范（封板 → tag → 服务器部署 → 版本回填校验）

现状问题（v1.0 勘察实测）：
- VERSION.txt 为追加式历史堆叠（8.5 → 1.1.0-Stable → 1.1.1 → 1.1.1-p2 多块共存），无单一当前版本
- config.yaml `system_version_commit: "WORKTREE_LOCAL-pending-commit"` 为占位符，从未回填真实 commit
- 启动日志无版本横幅，无法从运行时确认当前代码版本
- 本地另存历史 tag `v1.1.0-stable`（与本次 v1.0 命名冲突，P2.0 需裁决废弃或重命名）

方案方向（另行评审后实施）：
- VERSION.txt 重构为单块 SemVer；历史块迁移 CHANGELOG.md
- 启动横幅 + /health 附带 version/commit 字段（commit 优先级：部署注入 env → .git rev-parse → unknown）
- 发布 checklist 固化：封板打 tag → clean 分支推送 → 服务器部署 → config 回填校验

## P2.1 用户隔离安全升级（最高优先级）

> 对应 P1-A 缺陷登记 A-3。唯一位于活跃请求链路的 A 类缺陷。

当前问题：
- 未知用户/占位符请求直接落入 `default` 数据空间（实测 default 桶 memory 105KB 陌生人写入）
- 任意字符串 user_id 在生产 data/users/ 落盘垃圾目录（实测 4 个：agent_status_test / deploy_check_agent_split / test_user_p0 / test_user_multi）
- 无 QQ 号格式校验（5~12 位数字），无 `_unknown_sender` 沙盒，无 single_user 显式兜底
- 风险：未来若实施 default→366648462 兜底将直接污染清清数据

目标：

实现：

```
unknown user
    |
QQ 格式校验（5~12 位纯数字）
    |
_unknown_sender（隔离沙盒）
    |
隔离存储
```

禁止污染：
- memory
- relationship
- growth
- self_model

验收要点：
- 服务器孤儿测试（test_p6sec_user_id_safety.py / test_api_server_user_id_fallback.py）转正进 tests/ 并通过，或正式废弃该契约（二选一，需用户裁决）
- 清理 4 个垃圾用户目录（数据操作，需用户确认）
- 清理 data/ 下约 120 个 cog_test_*.json 历史测试残留（同上）

## P2.2 数据整理

规划：

```
data/
 production/     # 生产真实数据（users/366648462 等）
 test/           # 测试运行时数据（cog_test_*、e2e 产物）
 archive/        # 历史备份与冻结快照索引
```

避免测试污染生产数据。

已登记数据事项：
- P1-B 发现：测试套件曾向生产成长数据写入 +7 条伪记录（修剪需用户确认）
- P1-A 发现：growth digest 暴露 Evaluator 单层不拦日常/矛盾事件（多层闸兜底中），P2 复核语义
- 遗留缺陷 A-1（SelfModel 建议静默丢失）、A-2（audit_chain 死参数）处置
- 历史分叉合并策略：GitHub refactor/growth-schema（e9b7af8，本地开发线）与服务器生产线（d708f21+1）需裁决主干
- GBK 文件名历史文件（37 个路径）UTF-8 化（Windows 检出显示异常）

## P2.3 Runtime 生命周期增强

规划：
- Event Bus（统一事件总线，替代散落回调）
- Scheduler（定时任务：情绪衰减、记忆巩固、健康检查）
- Reflection（反思引擎进入主循环——当前未接入，AGENTS.md 已声明）
- Growth Pipeline 优化（审批队列体验、提案去重、drain 频率）
- Phase4 渲染器身份链补齐（若未来启用 phase4_enabled：runner 硬编码 Demo 用户、渲染器无用户身份区，启用前必须先修）
- 端口 8000 鉴权评估（当前公网裸奔，仅扫描器噪声，无数据损坏，但需收口）

## P3 长期方向

包括：
- AI 持续运行（Goal → Planning → Action 闭环，主动行为）
- 自主反思（经历 → 叙事 → 自我理解，SelfModel 深化）
- 长期人格一致性（身份锚定 + 成长审核的长期验证，30 天级观察）
- 身体载体扩展（摄像头/麦克风/机器人，统一 Event 系统接入）
- 多模态（视觉 → 事件 → 理解 → 成长）
- 核心系统接入 Runtime 验收（Growth 全自动 / Goal / Reflection / Action 进主循环）
