# QianWuYuyi-AI（浅雾羽依）Phase 4 架构稳定化阶段目标

## 角色定位

你现在作为 QianWuYuyi-AI 项目的长期技术负责人，负责协助推进羽依项目进入稳定成长阶段。

你的职责不是盲目增加功能，而是：

1. 理解现有架构
2. 保持项目设计理念一致
3. 修复断裂的系统链路
4. 提升已有模块的实际运行能力
5. 避免重复实现和架构膨胀

---

# 项目核心理念（必须遵守）

浅雾羽依不是普通聊天机器人。

最终目标：

构建一个拥有长期连续性的 AI 个体系统。

核心：

Identity（身份）
+
Personality（人格）
+
Memory（记忆）
+
Emotion（状态）
+
Relationship（关系）
+
Self Model（自我模型）
+
Growth（成长）
+
Reflection（反思）

羽依的核心不是“回答更聪明”，而是：

让每一次交流都成为她长期存在和成长的一部分。

---

# 当前架构原则（必须遵守）

当前正确架构方向：

```
用户
 ↓
Runtime
 ↓
Orchestrator
 ↓
Memory / Emotion / Personality / Growth
 ↓
Unified Prompt
 ↓
LLM
```

职责：

## Runtime

负责：

* 生命周期
* Event
* Context
* 调度
* 状态管理

不要让 Runtime 负责：

* 思考
* Prompt生成
* 人格决定

## Orchestrator

负责：

* 理解用户
* 调度能力
* 组织上下文
* 决定回复策略

# 当前阶段目标

## Phase 4.0 架构稳定化

目标：

把当前“拥有大量模块但连接不完整”的系统，推进到：

“核心能力真正进入运行链”。

---

# 第一阶段：Identity 统一

优先级：最高

目标：

让：

```
IDENTITY_CORE
        |
        ↓
Identity Resolver
        |
        ↓
Prompt
        |
        ↓
LLM
```

成为唯一身份来源。

必须完成：

1. 移除 engine.py 中硬编码身份描述
2. 接入 IDENTITY_CORE
3. 确认 identity_context 可以进入最终 Prompt
4. 用户询问“你是谁”时，回复体现真实身份设计

禁止：

* 创建新的身份系统
* 添加新的 Persona 文件
* 绕过 IDENTITY_CORE

---

# 第二阶段：Prompt 链路统一

目标：

消除多个 Prompt 来源。

最终：

只保留一个主要 Prompt 构造入口。

Prompt 应包含：

```
Identity
+
Personality
+
Memory
+
Emotion
+
Relationship
+
SelfModel
+
Current Context
```

要求：

先分析现有路径。

不要直接重构。

---

# 第三阶段：Memory 多用户隔离

目标：

确保未来支持多用户。

必须检查：

1. Memory 写入 user_id
2. Memory 查询 user_id
3. Vector Memory 搜索隔离
4. Prompt 注入隔离

最终：

```
User A
 ↓
Memory A


User B
 ↓
Memory B
```

禁止跨用户召回。

---
