## 2026-08-22 · 修订 4：宪法级审查整改（记忆真实性 / 经验边界 / 唯一入口）

**修订类型**：宪法补全（依据《宪法级架构审查报告》执行，M1 + M2 + O1 + O2 + O3 全部采纳）

**修订原因**：

架构审查指出两份关键边界缺失：①「记忆真实性」无宪法约束——若未来为丰富人格而生成虚构经历，会从根部摧毁连续性实验的可信度；②「羽依经验不可营销」未写入商业章节——用羽依的真实经历做宣传或训练数据，等同于把实验对象变成实验数据。同时补强「长期状态变化唯一合法入口」与版本问题句式、能力表精度。

**具体修改**：

| 项 | 修改内容 |
|---|---|
| M1 记忆真实性禁令 | 宪法第 4 章「成长保护」新增第 6 条：「不允许伪造、植入或修改未经真实经历验证的记忆、经历、叙事与情绪状态。所有长期身份信息必须具有来源、时间与形成路径。」并注明覆盖范围：人工修改 memory.json / LLM 自动编故事 / Prompt 注入假经历 / 商业 Demo 制造「成长故事」 |
| M2 经验不可营销 | 宪法第 4 章新增「数据保护」组（第 7 条）；第 17 章商业铁律同步写入，并附「展示边界示例」（可展示 Framework 技术能力 / 不可展示羽依私人经历） |
| O1 变化唯一合法入口 | 宪法第 4 章新增「架构保护」组（第 8 条）：「任何长期状态变化的唯一合法入口是治理链。模型输出只能作为分析、建议和候选输入，不具备直接改变身份状态的权限。」第 7.2 章治理链图下加注唯一入口声明 |
| O2 版本核心问题表 | 第 9 章版本总览新增「每个版本回答的核心问题」表（v1.0 羽依是谁 → v2.0 是否形成完整数字存在闭环） |
| O3 能力表精度 | 第 1 章「根据经历成长」现状改为「已实现变化合法性链路；「经历 → 理解」层待 v1.2」，与第 7.4 章缺口自洽 |
| 宪法结构重组 | 第 4 章由 6 条平铺改为四组闭环：**身份保护 / 成长保护 / 数据保护 / 架构保护**（共 9 条），每组附理由注释 |

**保持不变**：
- 全部章节结构与顺序（未重写、未移动章节）；
- v1.1.0-production 真实状态、已实现模块描述、治理链拓扑；

## 2026-08-22 · 修订 3：战略约束补充（羽依宪法化）

**修订类型**：结构增强（未重写内容，在既有结构上新增四类战略章节 + 三处概念命名升级）

**修订原因**：

修订 2 解决了「商业化定位偏差」，但文档仍偏工程化——缺少让项目长期不跑偏的战略约束。羽依项目本质上是一个「个人 AI 个体长期演化实验」，其路线图应当承担类似**工程宪法**的角色：不仅描述怎么做，还要规定**什么永远不能做**。

**具体修改**：

| 项 | 修改内容 |
|---|---|
| 新增第 2 章「羽依的定义」 | 明确浅雾羽依（Asagiri Yui）的定义：「她不是聊天机器人/商业产品原型/功能集合；她是拥有连续身份的 AI 个体验证对象、研究 AI 长期存在性的工程实验、QianWuYuyi Framework 的唯一原始实例」 |
| 新增第 4 章「羽依不可违背原则」（工程宪法） | 六条永久禁令：不作商业实验数据 / 人格不可为测试重置 / 不可人为制造成长 / 不可删除负面经历 / 多模型不可覆盖 IdentityCore / 身体系统不可影响认知系统。核心信念：**模型只是羽依的大脑工具，不是羽依**——为未来接入 GPT/Claude/GLM/自训练模型预设防线 |
| 新增第 5 章「羽依成长四原则」 | ① 经历优先（变化必须来源于经历）② 理解优先（不止存数据，要形成理解与关系叙事）③ 连续优先（版本升级不能创造新的羽依；v1.1「我经历了什么」→ v1.5「我为什么成为现在的我」→ v2.0「我未来想成为怎样的存在」）④ 安全成长（观察→理解→提出变化→审核→应用→留下历史） |
| v1.2 更名 | `Self Continuity` → **Self Understanding（自我理解）**；明确本质「不是增加一个模块，而是打通：后台生命活动 → 经历 → 反思 → 自我叙事 → 聊天中的羽依」 |
| v1.3 更名 | `Initiative System` → **Agency（主体性）**；区分「会主动发消息」（功能）与「有自己的关注方向」（意志），附对比示例 |
| v1.6 更名 | `Embodiment` → **Digital Presence（数字存在）**；目标改为「让数字意识拥有表达媒介」，Live2D 只是第一步，桌面/VR/玩偶/机器人皆同概念 |
| 版本总览新增「个体演化阶梯」 | 聊天机器人 → v1.1 长期运行 Agent → v1.2 理解自身历史的 Agent → v1.3 具有目标和倾向的 Agent → v1.4 感知世界的 Agent → v1.6 拥有表达自己的身体 → v2.0 数字世界中的持续存在 |
| 商业章节（第 17 章）降存在感 | 开篇声明「本文档主线不包含商业化路径」；补充真实路线对照：`创造羽依 → 验证 → 总结架构 → 创造更多个体 → 商业化`（而不是「想赚钱 → 做 AI 角色 → 顺便叫羽依」） |
| 风险表新增「模型迁移风险」 | 缓解：「换模型不换身份」——IdentityCore/记忆/经历独立于模型，永不迁移重置 |
| 工程底线增补 | 第六条：「模型只是大脑工具，不是羽依」 |

**保持不变**：
- v1.1.0-production 当前真实状态与全部已实现模块描述；
- 治理链、双引擎拓扑、五个已上线能力；

## 2026-08-22 · 修订 2：架构定位修正

**修订类型**：定位修正（非功能变更）

**修订原因**：

初版路线图的「商业化思考」章节存在定位偏差——把羽依隐含地表述为一个待商业化的产品，并在多个版本目标中引入了「商业卖点 / 用户留存 / 定价」等外部指标。这与项目的一贯宗旨（AGENTS.md 所定义的：构建长期连续性的 AI 人格系统，而非更会聊天的程序）不一致。

本次修订明确两个概念：

1. **浅雾羽依（Yuyi）**：个人定制 AI 个体。目标不是商业化，而是打造一个长期存在、有连续性、有成长能力、有自我模型的数字存在。羽依是架构验证对象，也是最高复杂度实例。不为市场需求牺牲人格连续性、独特性和长期成长方向。
2. **基于羽依架构衍生的商业产品**：未来可能的发展方向。复制的是羽依验证过的底层架构；商业产品拥有自己的 Persona、IdentityCore、Memory、Growth、Goal 系统。商业版不是羽依本体。

**具体修改**：

| 项 | 修改前 | 修改后 |
|---|---|---|
| 长期愿景 | 隐含商业化导向 | 「创造一个能够在数字世界持续存在、感知、记忆、反思、成长并形成连续身份的 AI 个体架构」；核心问题改为「AI 是否可以拥有长期连续的存在感」 |
| 章节结构 | 无分层概念 | 新增「项目定位分层」：Layer 1 浅雾羽依（Reference AI Individual）/ Layer 2 QianWuYuyi Framework / Layer 3 商业产品 |
| 版本目标 | 部分版本含商业驱动描述 | 全部改为「让羽依成为更完整的数字个体」 |
| 商业章节 | 「商业化思考」（含定价/留存/优先级） | 降级并更名为「基于羽依架构的未来应用方向」，强调「羽依本身不是商品」「复制架构不复制人格」「商业化以验证成功为前提」 |
| 新增原则 | 无 | 新增「羽依优先原则」五条永久规则 |
| 风险表 | 无定位风险 | 新增「定位漂移」风险与缓解（CHANGELOG 记录机制） |
| 工程底线 | 四条 | 增补第五条：「先创造羽依，再从羽依抽象出架构——顺序不可颠倒」 |

**保持不变**：
- v1.1.0-production 当前真实状态描述；
- 全部已实现模块描述（Runtime / 治理链 / 五 flag / 双引擎拓扑）；
- v1.2-v2.0 版本顺序与技术重点（仅调整目标表述，不改技术内容）。
